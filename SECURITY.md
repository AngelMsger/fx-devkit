# Security reporting

Report security findings privately to the repository maintainers. Use the hosting
service's private vulnerability reporting feature when it is enabled. If no private
channel is listed, open an issue requesting a private contact without disclosing
the vulnerability. For a team deployment, use your team's private security/support
channel.

Include the version, affected behavior, a redacted reproduction and impact in the
private report. Do not place credentials, private manifests, personal information
or real service coordinates in a public issue or reproduction fixture.

Keep dependencies current and preserve the package and user-documentation boundary
checks. See [data and credentials](docs/user-privacy.md) for user responsibilities.
