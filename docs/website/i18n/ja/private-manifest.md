# データと資格情報

チームのマニフェストにはリポジトリ、ツール、サービスの座標を記述します。必要な人だけがアクセスできるチームのリポジトリに保管してください。fx の利用にマニフェストの公開は不要です。

## ローカルの状態 {#what-stays-on-your-machine}

fx は登録したワークスペース、個人の選択、設定、信頼判断、操作状態を既定で `~/.fx` に保存します。`FX_HOME` で場所を変更できます。マニフェストの checkout は業務リポジトリと分けて保存されます。

`fx config export` は対応する設定と個人レイヤーを出力し、資格情報、信頼記録、マニフェスト clone は含めません。ただし、リポジトリの選択や上書き設定にチームの情報が含まれる場合があるため、共有前に内容を確認してください。

## 認証 {#authentication}

資格情報は各連携ツールが管理します。通常のログイン手順を使い、token をマニフェストや共有 Agent 指示に書き込まないでください。アクセス不足の場合、fx は準備状態を確認して必要な設定手順を案内します。

一台で環境を選択しても、別のマシンでのアクセス権の証明にはなりません。`fx can <capability> --env <environment>` または `fx doctor` で確認してください。

## チームの知識 {#sharing-team-knowledge}

共有リポジトリ情報、環境の座標、チーム Skill は管理されたマニフェストソースに置きます。メンバー文書の `sensitive: true` は必須ですが、リポジトリのアクセス制御の代わりにはなりません。

選択したソース変更の提出は、明示的に `fx source push` を実行したときに行います。先に `--dry-run` でファイルと宛先を確認してください。通常のワークスペース同期は、ソースを公開する指示ではありません。

## 問題の報告 {#reporting-a-problem}

公開の報告には機密情報を除いた最小限の例だけを含めてください。資格情報、メンバー情報、非公開のサービス座標を削除します。[サポート](support.md)を参照してください。
