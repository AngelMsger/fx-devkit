# 公開ツールと非公開のチーム設定

fx-devkit の公開は、チームのワークスペースの公開を意味しません。メンバーは引き続き組織のリポジトリ、サービス環境、連携 CLI、既存のアクセス制御を利用します。

## 公開リポジトリに含めるもの {#keep-in-this-repository}

- CLI 実装、provider アダプター、ネイティブ Agent プロトコル。
- スキーマ、一般的な利用ガイド、架空の例。
- 実際のプロトコルの意味を保った合成データとオフラインテスト。
- 内蔵 fx-workspace Skill と一般的な開発ガイド。

## チームの非公開ソースに置くもの {#keep-in-the-teams-private-source}

- 実際のリポジトリ URL、ブランチ、担当者、アクセスの問い合わせ先。
- 環境のホスト、ログストリーム、エラー追跡プロジェクト、ビルドジョブ、クラスタ座標。
- 複数リポジトリにまたがる業務アーキテクチャと製品固有の手順。
- チーム Skill、承認済みのケース定義、適切に制限された評価の根拠。

非公開マニフェストも Git でバージョン管理できます。`init`、`sync`、`manifest`、`member`、`where`、`release`、`source push` の役割は変わりません。Provider とインストーラーは引き続き宣言で設定します。ソースの公開を理由に連携を無効化したり、プライベートなサービスを公共サービスに置き換えたりしません。

## 各マシンに保存するもの {#keep-on-each-machine}

資格情報は各連携ツールが管理します。FX_HOME には選択、設定、信頼記録、操作状態があります。エクスポートには秘密、信頼記録、マニフェスト clone は含まれません。他のマシンでの成功は、このマシンの準備完了を証明しません。

## 例と互換性 {#examples-and-compatibility}

example を含む名前と example.com のホストは架空の例です。実組織の既定値ではありません。リポジトリ名とサービス名は異なる場合があるため、必要なら `obs.svc` を指定してください。従来の `fx-` 命名規則は互換性のために残していますが、新規マニフェストでは必須ではありません。

予定されている public npm パッケージにプライベートレジストリの権限は不要です。チームの非公開マニフェスト、連携パッケージ、サービスは別々に管理できます。fx 自体の配布と更新には[レジストリ移行](design/registry-configuration.md)が必要です。ツールは [Apache-2.0](../LICENSE) で提供します。このライセンスは非公開マニフェストやサービスへのアクセス権を付与しません。
