# 変更履歴

## [Unreleased]

- 公開パッケージ `@angelmsger/fx` を npmjs で公開し、各バージョンタグの GitHub Release に tarball を添付します。内部の `@fx/devkit` チャネルは変わりません。
- `fx release` の human 出力をリポジトリごとにまとめます。失敗または警告のチェックがあるリポジトリはそれぞれのブロックでそのすべてのチェックを示し、だれもサインインしていないツールのようにすべてのリポジトリに共通する問題は、解決するコマンドとともにその上に 1 回だけ示します。すべてのチェックが通ったリポジトリは最後の 1 行にまとめます。`--details` を付けると、それらのチェックも一覧します。JSON と NDJSON の出力は変わりません。

## 0.10.0 (2026-10-10)

- 対象を指定しない `fx can` が、このワークスペースで問い合わせできる能力を一覧します。manifest が結び付けられる能力ごとに 1 行、環境単位の能力は platform インスタンスごとに 1 行で、スコープ、provider、対応 CLI、用途を示します。何も結び付けられていない能力は provider なしの行として残ります。一覧は結び付けだけを読み取り、個別の能力を問い合わせたときは従来どおり準備状況を確認します。
- 準備チェックが失敗したときに、何と答えたかを示します。`can`、`where`、`doctor`、`login` の handoff にある保留中の各ステップに `check` が付きます。内容はツール自身の言葉、またはそのステップが待っている別のステップです。fx が失敗を読み取れる場合は原因も示し、ステップの手順はその原因に応じた対処に置き換わります。
- クラスターで認証が確立されなかった場合、「いいえ」と答えた場合、到達できなかった場合を区別します。クラスターがリクエストを誰のものとも認めなかったときは、クラスターの所有者にロールを依頼する案内ではなく、kubeconfig とそのサインイン方法の確認、および更新された kubeconfig の入手先を案内します。
- kubeconfig が宣言された context を含むかどうかを、クラスターに接続せずに確認します。クラスターへのアクセスチェックは、各リクエストを 5 秒に制限します。
- チェックから答えが得られなかった場合（ツールが起動しなかった、または期限内に終わらなかった）、`can` と `where` は `unknown` を返し、そのチェックを `unfinished` に挙げます。1 つのプラットフォームが応答しないことを理由に、`where` が同じリポジトリのすべてのプラットフォームで失敗することはなくなりました。ツールが起動しなかった場合、`doctor` と `login` はそのステップを人に引き継がず、ツールがないことを報告します。
- 環境がプラットフォームを対象にしていない理由を `<env> declares no <platform> platform` と示します。別のプラットフォームについて書かれている可能性がある環境のメモは、その理由として使われなくなりました。
- `fx login` は普段使う環境を尋ねなくなりました。個人の環境選択は `fx env select` だけで設定します。未設定の間は宣言されたすべての環境が対象となり、`--env` で環境を指定しないログインはその旨と絞り込み方を知らせます。これまでは `--env` で環境を指定していても尋ねられ、「すべて」と答えた人はログインのたびに再び尋ねられ、その場でログインする環境だけを答えると以後 `fx doctor` と `fx sync` の対象が狭まっていました。
- `fx can` が認識できない対象を受け取ったとき、fx 自身が担う内部の能力を候補に挙げなくなり、次の手順として `fx can` と `fx tool list` を案内します。

## 0.9.1 (2026-10-09)

- `init`、`sync`、`doctor` が未完了のときの端末出力で、理由と解決コマンドが同じチェックを 1 行にまとめ、実行できなかったチェックと実行して失敗したチェックを別の記号で区別します。
- 完了できなかったチェックにサインインを求めなくなりました。対応 CLI のチェックがタイムアウトした場合は、再チェックだけを案内します。
- 同梱の対応 CLI が示す未準備の理由をそのまま表示します。たとえば `OpenObserve returned HTTP 401` や、サインイン不要のサーバーへのリクエスト失敗です。`expected authenticated to be true` だけの表示ではなくなりました。
- fx 自身が更新できる Skill のコピーには `fx doctor --fix` を案内します。
- 宣言されたサービスに到達できる対応 CLI の context は、所有者がどの方式でサインインしていても受け入れます。`service` 宣言の `auth_scheme` は、fx が context を作る方法と `fx login` が案内するサインイン方式だけを決めます。準備、チェック、クエリは宣言された URL、flavor、組織だけを確認し、`--auth-scheme` を渡さなくなりました。既存の context にこれらの項目のいずれかが欠けている場合は、その項目だけを補い、宣言されたサインイン方式は指定しません。以前は、別の方式でサインインしている context と競合していました。
- 明示的に `fx sync` を実行するたびに、既存のログインを関連付けます。`fx init` のときだけではなくなりました。sync は init と同じくローカルの prepare フェーズの設定手順を実行するため、引き継げるログインが `fx doctor --fix` の実行を待つことはありません。個人のサインインは引き続き本人が行い、バックグラウンド hook は確認だけを行います。
- fx が意味を把握しているチェックでは、満たされなかった内容をそのまま示します。`fx doctor --fix` で関連付けられる既存のログインには `an existing login can be reused` を、WeCom の 3 つのチェックにはレスポンスのエラーコードで判定したうえで `the WeCom API returned an error` を表示します。

## 0.9.0 (2026-10-09)

- ワークスペースルートには `AGENTS.md` だけを派生します。fx はそれを指す `CLAUDE.md` を書き込まなくなり、`fx manifest render` も manifest リポジトリにこのファイルを作成しなくなりました。Claude Code 2.1.277 以降は `AGENTS.md` を自分で読み込み、`CLAUDE.md` があればそちらを代わりに読み込むためです。`fx sync` は以前のバージョンが派生したポインターを削除し、削除されるまで `fx doctor` はガイドが古いと報告します。自分で書いた `CLAUDE.md` はそのまま残り、ガイドの競合としても扱われなくなります。Claude Code が引き続きガイドを読み込むよう、先頭に `@AGENTS.md` を書いてください。manifest リポジトリにこのポインターが残っている場合は削除してください。
- manifest ソースのペイロードから `CLAUDE.md` を外しました。ディレクトリソースにあるこのファイルは管理対象のソースへコピーされなくなり、stdin バンドルが指定している場合は `MANIFEST_SOURCE_INVALID` で拒否されます。
- コマンドが動作中であることを表示します。開始から 0.5 秒を過ぎると、端末にその場で描き直されるステータス行が 1 行表示されます。経過時間、数えられる作業の進み具合、もっとも長く続いている項目を示し、たとえば `doctor 23s  checks 69/82  kubectl.access@dev 3s` のようになります。fx が待つ外部呼び出しは起動する場所で報告されるため、すべてのコマンドにこの行があります。`doctor`、`sync`、`init`、`status`、`release`、`login` はチェック、リポジトリ、ステップの数も数えます。結果、通知、各項目の結末はステータス行の上に書かれ、質問やサインインのコマンドは完了するまで端末を占有し、コマンドが終了または中断されるとステータス行は消えます。git やインストーラーの実行中は、同じ端末でホスト鍵やパスフレーズを尋ねられることがあるため、その下では描き直さず、ステータス行を 5 秒ごとに 1 行として出力します。ステータス行を表示する端末では、項目ごとの `start` 行とリポジトリのハートビートは表示しません。ステータス行が同じ内容を示すためです。パイプ、ファイル、CI、`TERM=dumb`、`--quiet`、JSON と NDJSON の出力にはステータス行を出力せず、読み取れる内容はこれまでとまったく同じです。

## 0.8.0 (2026-10-09)

- fx が同梱ツール向けに定義するコマンドは、信頼の確認を求めなくなりました。マニフェストの `service` 宣言が引数を埋めるサービス準備、ログインの再利用、認証情報の確認も含みます。確認が必要なのは、チームの `tools.yaml` パッチが記述した実行ベクトルだけです。保存済みの認証情報をどこへ送れるかは対応 CLI が判断します。
- `init`、`sync`、`doctor` が未完了のときの端末出力を整理しました。各ブロッカーをチェック ID 付きで表示し、サインインコマンドはツールごとに環境をまとめ、PATH で `fx` が見つかる場合はコマンドを `fx` と表記し、端末では出力の後に `PREPARATION_INCOMPLETE` のエラーエンベロープを重ねて出しません。JSON 出力は変わりません。
- 対応 CLI の Skill インストールの進捗は、Agent ディレクトリごとではなくツールごとに 1 回だけ報告します。
- チームが記述した対応 CLI の Skill コマンドは 1 回の確認で済みます。fx が付け加える Agent 名やディレクトリによって、対象ごとに別の実行ベクトルとして確認を求めることはなくなり、既存の承認もそのまま有効です。
- 対応 CLI のチェックが失敗した理由を、ツール自身の言葉で示します。出力されたエラーオブジェクトのメッセージを読み取り、ログ行と警告を除き、失敗箇所に続く行を残し、JSON チェックが期待する値を `expected authenticated to be true` のように示します。
- human 出力を端末で読みやすくしました。見出し、状態を表す語、ゼロの件数を色で区別し、チェック一覧と進捗には状態記号を付け、入力するコマンドを目立たせ、表は端末の幅に合わせ、ブロッカーの長い理由は自分の列の下で折り返し、エラーは JSON エンベロープではなくヒント、次の手順、引き継ぎ事項を添えたテキストで表示します。装飾するのは端末だけで、stdout と stderr は別々に判定します。環境変数の設定にかかわらず、パイプ、ファイル、CI にはプレーンテキストと JSON のエラーエンベロープを出力し、JSON と NDJSON の出力は変わりません。`NO_COLOR` は色だけを消し、記号は残します。
- human の表を端末の桁幅で揃え、CJK 文字を含む行がずれないようにしました。一覧と末尾の情報の間に空行を入れ、値のない項目の後ろに行末の空白を残さず、レコード内の一覧は 1 件でも長くなるとフィールドごとに 1 行で表示し、空のフィールドを省きます。
- ルートヘルプは端末でも日常コマンドの見出しを `EVERYDAY` と表示し、`FIRST WORKSPACE`、`AGENT USAGE`、`COMPATIBILITY` の見出しもほかの見出しと同じく強調します。

## 0.6.0 (2026-10-08)

- `metrics` を実装しました。`prometheus-cli` provider を追加し、この CLI を同梱カタログに加えています。サービスの座標は scrape job です。`where` は宣言されたサーバーに固定した `up{job="..."}` クエリを出力します。何にも一致しないセレクターでも成功するため、probe は提供しません。
- service 宣言の `auth_scheme` で `none` と `bearer` を受け付けます。サインイン不要と宣言されたサーバーは応答の有無で準備完了を判定し、ログインを要求しません。
- オンライン会議、録画、議事録を保持する会議システムを表すワークスペース能力 `meeting` を追加しました。`tmeet` で動作する `tencent-meeting` provider を提供し、`tmeet` を同梱カタログに加えています。`calendar` は予定と空き時間を扱います。

## 0.4.0 (2026-09-21)

- 承認済みのローカル準備を初期化で実行し、個人認証をまとめて引き継ぎます。`init --resume` は完了済みの作業を保持します。
- `preparation.state` と具体的な復旧操作を統一しました。準備未完了は終了コード 12、任意のホスト有効化は別に報告します。
- 無効なマニフェストを変更前に拒否し、共有ソースを保持して生成ガイドを補完します。ツール schema は 3、run 手順は prepare/authenticate を宣言します。
- 自己更新とバージョン取得で npm の scope/既定 Registry と認証設定を再利用します。`FX_REGISTRY` は任意の上書きとなり、公開依存パッケージの既定経路を維持します。

## 0.3.0 (2026-09-20)

- ログインの手動操作待ちや例外発生時に、部分結果、集計、構造化された復旧情報を保持します。非ゼロ終了でも有効な stdout が残る場合があります。
- manifest とガイドの書き込み中の並行編集を保護します。承認済みの置換は元のオブジェクトをバックアップへ原子的に移動し、失敗時にもファイルごとの結果を保持します。
- 初期化と同期の準備完了状態を明示し、名前や説明を段階の失敗と誤判定する問題を修正します。
- 自己更新のインストーラー出力による JSON の混入を防ぎ、復旧手順とソース・公開済み機能の違いを説明します。

- `calendar`、`task`、`worklog`、`metrics` の能力を追加しました。前 2 つには Lark と WeCom の provider、worklog には Jira の provider があります。`metrics` は名前だけで実装はなく、マニフェストで記述はできますが結び付けには provider が必要です。`im` は「メッセージ」だけを指すようになりました。
- Jira の issue tracker と Lark wiki の knowledge base を追加し、それぞれの能力に 2 つ目の実装ができました。1 つの連携 CLI が複数の能力を担っても、インストールと確認は 1 回だけです。
- workspace のツールチェーンを、結び付けた provider から導出するようにしました。同梱ツールを二度宣言する必要はなくなり、`tool list` は各ツールが結び付けによるものか manifest の宣言によるものかを示し、`--catalog` は残りを表示します。
- manifest が同名のツールを宣言している場合、fx が実装していない provider も能力に結び付けられるようにしました。同梱ツールの名前に似ているだけの id は、そのまま受け入れず訂正を促します。
- tools ドキュメントの `defaults` ブロックで `install_on_init` を指定できるようにしました。個々のエントリでの上書きは従来どおりです。
- provider が結び付いているのに tools ドキュメントがその配下のツールを宣言していない場合を `TOOL_UNDECLARED` として報告し、provider が無いという誤った説明をやめました。
- platform の `service` を、その名前が示す provider の宣言と照合するようにしました。正しい宣言を誤って拒否せず、誤った宣言も見逃しません。
- session-start の背景処理が実施する phase を事前に記録し、途中で終了させられた worker が到達しなかった phase を `HOOK_PHASE_UNREPORTED` として残すようにしました。
- session-start の背景実行では、配下のコマンドが 1 つ持ち時間を使い切っても実行全体を終了せず、以降の phase が結果を残すようにしました。ホストが待っている前景の実行は従来どおりそこで終了します。
- 切り離された背景実行の終わり方を、workspace の `run` observation として記録するようにしました。これまで supervisor は誰も読まないストリームにしか書けませんでした。

- 全出力形式のレポート抽出、復旧コマンドの workspace 指定、貢献ロック内のソース同一性検証を修正。
- 検証済みローカル Git のインポートと一致する upstream の安全な追加に対応し、有効・必須ツールの宣言に準備判定を統一。
- 宣言された各 setup 検証形式を受け入れ、manifest のマージで null を許す比較値を保持。

- グローバルなワークスペース探索、状態診断、登録解除、移動先変更、ソース変更を追加。業務 checkout を保持し、同一ディレクトリの重複登録を防止。
- repo/env select に固定集合、将来の追加に追従する全選択、空集合を追加。初回 init のクローン前選択とローカルソースの具体的なプレビューに対応。
- 未追跡ファイルの状態フィルター漏れ、必須 manifest がない場合の検証成功、古い読み取り可否キャッシュによる復旧阻害を修正。
- doctor は宣言されたツールと有効な provider の依存関係を既定で検査。明示的なツール検査は保持。
- 互換性の注意：init の registered は実際の登録状態を示し、予定は plan に分離。config import は名前ごとにマージして未指定の登録を保持し、名前の省略で登録を削除しない。

- 互換性：`fx skill show` で bundled Skill がない場合は `BUNDLED_SKILL_MISSING` を返します。`SKILL_MISSING` は Agent 向け通知のみを指します。
